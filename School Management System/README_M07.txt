SCHOOL MANAGEMENT SOFTWARE — M07
Biometric / Camera Attendance Integration
==========================================

--------------------
Install M01 through M06 first. M07 uses the Student, StudentEnrollment,
School/Class/Section, StudentAttendance, AttendanceSource, Identity and Audit

WHAT M07 ADDS
-------------
1. Biometric device registry
   - Device code, name/model, connection type, IP/location, active state.
   - Strong per-device integration key generated by the software.
   - ONLY the SHA-256 hash of that key is stored in the database.
   - Key can be regenerated; old key immediately stops working.
   - Last sync/health message appears in Attendance Devices screen.

2. Biometric student enrollment mapping
   - Maps exact device user ID/reference to an existing active Student.
   - Supports Fingerprint, Face, Card/PIN and Other modality labels.
   - Optional device/provider template reference; actual template does not need
     to be stored in the school database.

3. Attendance event log
   - Records biometric/camera integration events separately from daily
     StudentAttendance.
   - Stores source, direction, time, device reference, processing result,
     confidence/face count when available, and review reason.
   - Statuses include Recorded, AttendanceApplied, Duplicate, Unmatched,
     NeedsReview and Rejected.

4. De-duplication / offline-safe API behavior
   - Exact Device + EventId is idempotent: re-sending the same event does not
     create another attendance row.
   - Repeated scans inside the configured DuplicateWindowSeconds are ignored
     as attendance changes and logged as Duplicate.
   - This supports a local biometric bridge queue: if internet/server access is
     temporarily unavailable, the bridge can send its queued events later with
     the same EventId values.

5. Biometric bridge API
   POST /api/attendance/bridge/events
   POST /api/attendance/bridge/heartbeat

   Authentication uses:
   X-Device-Key: <the one-time device key shown after device creation>

6. Camera attendance UI
   - Browser camera permission through getUserMedia.
   - Captures one current frame, not continuous raw video.
   - Optional browser face-count hint where FaceDetector is supported.
   - Manual verified fallback remains available.
   - Teachers only see/mark students from assigned class/sections; Principal/
     Admin can use all active students.
   - The captured frame is not stored by the default school application.

7. Pluggable automated face recognition
   - ICameraRecognitionProvider is the integration boundary.
   - M07 ships with ManualOnlyCameraRecognitionProvider on purpose.
   - Manual camera verification works now.
   - Automatic face matching/enrollment becomes active only when a school-
     approved recognition provider is implemented and registered in Program.cs.
   - A successful automatic match must have one face, meet the configured
     confidence threshold, have an active local CameraFaceEnrollment, and pass
     the logged-in user's class-access check.

8. Safety / conflict behavior
   - IN biometric/camera event can create Present attendance when no attendance
     exists for that student/date.
   - OUT events are logged but do not rewrite daily attendance.
   - If daily attendance already says Present/Late, the event is linked/logged
     without creating a duplicate.
   - If daily attendance already says Absent/Leave/HalfDay/etc., M07 does NOT
     silently overwrite it. It creates a NeedsReview event for staff review.
   - Manual attendance from M06 always remains available.

FIRST TEST — BIOMETRIC DEVICE
-----------------------------
1. Login as Principal/Admin.
2. Open Attendance Devices.
3. Add Device, for example:
   Device Code: BIO-GATE-01
   Name: Main Gate Fingerprint
   Connection Type: LAN / SDK
4. Save.
5. COPY the displayed X-Device-Key immediately. It is shown once.
6. Click Map User and map the device user reference to a student.

TEST BRIDGE EVENT FROM POWERSHELL
---------------------------------
Replace the URL and key with your own values:

$headers = @{ "X-Device-Key" = "PASTE-ONE-TIME-DEVICE-KEY" }
$body = @{
    deviceCode = "BIO-GATE-01"
    eventId = "TEST-0001"
    deviceUserReference = "10025"
    occurredAt = "2026-09-21T08:30:00+05:00"
    direction = 1
    rawReference = "manual-api-test"
} | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri "https://localhost:YOURPORT/api/attendance/bridge/events" `
  -Headers $headers `
  -ContentType "application/json" `
  -Body $body

Direction values:
0 = Unknown
1 = In
2 = Out

Expected first IN event:
- API response status: AttendanceApplied (if the student has a valid normalized
  enrollment for that date and no conflicting attendance exists).
- Student Attendance screen shows Present with Source=Biometric.
- Attendance Devices screen shows the event.

Send the SAME eventId again:
- No duplicate attendance is created.
- Existing event result is returned.

Send a different eventId for the same student inside 60 seconds:
- It is logged as Duplicate and does not create another attendance record.

Send an unknown deviceUserReference:
- Event appears as Unmatched in Attendance Devices.

CAMERA ATTENDANCE TEST
----------------------
1. Run the site on localhost/HTTPS (browser camera APIs require a secure context,
   except localhost is generally treated as secure by modern browsers).
2. Open Camera Attendance.
3. Click Start Camera and allow camera permission.
4. Capture Frame.
5. Because the default provider is ManualOnly, visually verify the student and
   select them in Manual confirmation/fallback.
6. Click Process Attendance.
7. Student should become Present with Source=Camera if no conflicting daily
   attendance exists.
8. Check Attendance Devices -> Recent Integration Events.

CAMERA FACE ENROLLMENT
----------------------
The Face Enrollment screen captures 3 temporary samples. With the default
ManualOnly provider it will clearly report that automated recognition is not
configured and it will not store those samples. When a real provider is added,
that provider returns a TemplateReference; only that reference is stored in
CameraFaceEnrollments.

CONFIGURATION
-------------
appsettings.json adds:

"AttendanceIntegrations": {
  "DuplicateWindowSeconds": 60,
  "CameraAutoAcceptConfidence": 0.85,
  "MaxCameraImageBytes": 2000000,
  "SchoolTimeZoneId": "Asia/Karachi"
}

Change SchoolTimeZoneId if this software is deployed for a school in another
zone. Device event timestamps should include their UTC offset.

IMPORTANT NOTES
---------------
- M05's normalized SchoolClassId/SectionId mapping must exist for a student's
  placement. Old legacy text-only placements should be mapped before testing
  device/camera attendance.
- M07 is currently STUDENT attendance because the Staff entity is introduced in
  M11. When M11/M12 are implemented, the same integration architecture can be
  extended to staff attendance without creating a separate device subsystem.
- Do not put actual biometric templates, face photos, or device secrets in source
  control.
- Use the physical-device vendor SDK/local bridge on the school PC to read the
  hardware and POST events to this API. Browser code is not expected to directly
  control every fingerprint device.
